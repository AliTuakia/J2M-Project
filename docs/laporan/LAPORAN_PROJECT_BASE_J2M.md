## BAB I — PENDAHULUAN

### 1.1 Latar Belakang

Perkembangan teknologi digital telah mengubah cara pelaku usaha dalam memasarkan produk dan menjangkau konsumen. Sektor otomotif, khususnya industri aksesoris sepeda motor, turut merasakan dampak pergeseran ini. Konsumen kini terbiasa mencari informasi produk, membandingkan harga, dan melakukan transaksi secara daring. Pelaku usaha kecil dan menengah (UKM) yang belum mengadopsi platform digital berisiko kehilangan potensi pasar yang semakin besar.

J2M (Jok Motor) merupakan usaha yang bergerak di bidang penjualan bahan jok sepeda motor dan layanan pembuatan jok custom. Produk yang ditawarkan meliputi busa, fiber atau tulangan jok, kulit jok biasa, kulit jok motif, latex, serta satu set jok custom yang dapat disesuaikan berdasarkan pilihan bahan, warna, motif, tekstur, dan model jahitan. Sebagai usaha yang mengandalkan keahlian khusus, J2M memiliki peluang untuk memperluas jangkauan pasar melalui pemanfaatan platform digital.

Berdasarkan kondisi tersebut, kelompok kami mengambil J2M sebagai objek bisnis dalam tugas Project Base. Proyek ini bertujuan membangun kehadiran digital J2M melalui pengembangan website e-commerce, pengelolaan media sosial, dan pemanfaatan marketplace. Seluruh pengembangan dilakukan dalam konteks simulasi akademik yang disesuaikan dengan kebutuhan tugas perkuliahan.

### 1.2 Rumusan Masalah

Berdasarkan latar belakang di atas, rumusan masalah yang menjadi fokus proyek ini adalah sebagai berikut:

1. Bagaimana merancang dan mengembangkan website e-commerce yang dapat menampilkan katalog produk J2M secara informatif?
2. Bagaimana mengimplementasikan fitur transaksi simulasi pada website yang mencakup keranjang belanja, proses checkout, dan pengelolaan pesanan?
3. Bagaimana memanfaatkan media sosial dan marketplace sebagai kanal pendukung pemasaran produk J2M?
4. Bagaimana mengintegrasikan berbagai platform digital agar membentuk ekosistem pemasaran yang saling terhubung?

### 1.3 Tujuan Proyek

Tujuan dari pelaksanaan proyek ini adalah:

1. Mengembangkan website e-commerce berbasis Laravel yang menampilkan katalog produk J2M beserta informasi harga dan deskripsi produk.
2. Membangun fitur transaksi simulasi meliputi registrasi pengguna, keranjang belanja, checkout, riwayat pesanan, serta panel administrasi.
3. Menghubungkan Instagram sebagai kanal promosi visual dengan website J2M.
4. Menghubungkan Shopee sebagai kanal marketplace pendukung untuk memperluas akses pelanggan ke produk J2M.
5. Mengintegrasikan seluruh platform digital sehingga membentuk ekosistem bisnis digital yang terpadu.

### 1.4 Manfaat Proyek

Manfaat yang diharapkan dari proyek ini terdiri atas:

**Manfaat Akademik:**
- Memberikan pengalaman kepada mahasiswa dalam menerapkan konsep bisnis digital melalui proyek berbasis praktik.
- Melatih kemampuan mahasiswa dalam pengembangan website, pengelolaan media sosial, dan pemanfaatan marketplace.
- Meningkatkan pemahaman mahasiswa terhadap arsitektur aplikasi web modern menggunakan framework Laravel.

**Manfaat bagi Objek Bisnis:**
- Menyediakan prototipe website e-commerce yang dapat menjadi acuan pengembangan kehadiran digital J2M di masa mendatang.
- Memberikan gambaran potensi pemasaran digital bagi usaha J2M melalui berbagai platform.

### 1.5 Ruang Lingkup Proyek

Proyek ini memiliki batasan sebagai berikut:

1. Website yang dikembangkan merupakan proyek simulasi akademik. Transaksi pembayaran dan pengiriman pada website bersifat simulasi, bukan transaksi nyata.
2. Pengembangan website menggunakan framework Laravel 13 dengan PHP 8.3, MySQL sebagai basis data, Blade sebagai template engine, CSS kustom, serta Vite untuk pengelolaan aset frontend.
3. Deployment website ditargetkan pada platform Vercel menggunakan Docker container dengan FrankenPHP sebagai runtime.
4. Pengelolaan media sosial dalam ruang lingkup proyek difokuskan pada Instagram.
5. Pemanfaatan marketplace dalam ruang lingkup proyek difokuskan pada Shopee.
6. Data produk yang digunakan mengacu pada informasi yang diperoleh dari pemilik usaha J2M.
7. Foto produk pada katalog website merupakan foto referensi yang disediakan oleh pemilik usaha. Foto pada produk jok custom merupakan ilustrasi, bukan desain akhir yang akan diterima konsumen.

## BAB III — IMPLEMENTASI DAN PENGEMBANGAN BISNIS DIGITAL J2M

### 3.1 Pengembangan Website E-Commerce

#### 3.1.1 Tujuan Pengembangan Website

Website J2M dikembangkan sebagai platform digital utama yang berfungsi untuk:

1. Menampilkan katalog produk J2M secara terstruktur dan informatif, lengkap dengan foto, harga, dan deskripsi produk.
2. Menyediakan fitur simulasi transaksi e-commerce yang mencakup registrasi pengguna, keranjang belanja, proses checkout, dan riwayat pesanan.
3. Memfasilitasi pengelolaan produk dan pesanan melalui panel administrasi.
4. Menjadi titik pusat informasi yang menghubungkan seluruh kehadiran digital J2M.

Perlu ditegaskan bahwa website ini merupakan proyek simulasi akademik. Seluruh transaksi yang terjadi pada website bersifat simulasi — tidak ada pembayaran uang sungguhan maupun pengiriman barang. Hal ini dinyatakan secara eksplisit pada antarmuka website melalui label "Checkout simulasi", keterangan "Tidak ada uang yang ditagih atau barang yang dikirim", serta persetujuan simulasi yang wajib dicentang oleh pengguna sebelum membuat pesanan.

#### 3.1.2 Teknologi yang Digunakan

Pengembangan website J2M menggunakan stack teknologi berikut:

| Komponen | Teknologi | Versi/Keterangan |
|----------|-----------|------------------|
| Framework Backend | Laravel | 13 (terkunci di 13.40.0) |
| Bahasa Pemrograman | PHP | ^8.3 |
| Basis Data | MySQL | Menyimpan data produk, pengguna, keranjang, pesanan, dan sesi |
| Template Engine | Blade | Template engine bawaan Laravel |
| Styling Frontend | CSS kustom | Dikelola pada `resources/css/app.css` dan dibundel oleh Vite |
| Build Tool | Vite | Mengelola bundling CSS dan JavaScript |
| Containerization | Docker | Multi-stage build untuk deployment |
| Web Server | FrankenPHP + Caddy | Berbasis image `dunglas/frankenphp:1-php8.3-bookworm` |
| Platform Deployment | Vercel | Container service dengan Docker runtime |

Arsitektur aplikasi mengikuti pola Model-View-Controller (MVC) standar Laravel. Backend menangani seluruh logika bisnis, validasi data, dan manajemen state melalui controller dan model. Frontend menggunakan template Blade yang di-render di sisi server dengan CSS kustom responsif.

#### 3.1.3 Fitur Website

Berdasarkan pemeriksaan source code, website J2M memiliki fitur-fitur sebagai berikut:

**A. Halaman Beranda**

Halaman beranda (`/`) menjadi titik masuk utama bagi pengunjung. Halaman ini menampilkan:
- Bagian hero dengan tagline "Dari bahan jok, sampai satu set custom" dan tombol navigasi ke katalog.
- Navigasi kategori produk (Bahan jok dan Jok custom) yang mengarahkan pengguna ke katalog dengan filter kategori.
- Enam produk pilihan dari katalog yang ditampilkan dalam format grid, lengkap dengan foto, nama, harga, dan rating.
- Ringkasan rating pengguna secara keseluruhan untuk produk aktif.
- Informasi layanan jasa custom jok.
- Bagian "Tentang J2M" yang menjelaskan profil singkat usaha.

**B. Katalog Produk**

Halaman katalog (`/produk`) menampilkan seluruh produk aktif dalam format grid dengan fitur:
- Pencarian produk berdasarkan nama (parameter `q`).
- Filter berdasarkan kategori produk.
- Paginasi dengan 12 produk per halaman.
- Setiap kartu produk menampilkan foto, kategori, nama, rating rata-rata, dan harga.
- Produk jok custom ditandai dengan label "FOTO HANYA ILUSTRASI" pada fotonya.

**C. Detail Produk**

Halaman detail produk (`/produk/{product}`) menyajikan informasi lengkap satu produk:
- Foto produk dalam ukuran lebih besar.
- Kategori, nama produk, dan harga dalam format Rupiah.
- Rating produk (rata-rata dan jumlah penilaian).
- Deskripsi produk. Untuk produk jok custom, deskripsi menjelaskan bahwa pelanggan dapat menentukan kombinasi bahan, warna, motif, tekstur, dan model jahitan.
- Formulir penambahan ke keranjang (memerlukan login) dengan input jumlah. Untuk produk custom, terdapat field tambahan berupa tipe motor (wajib) dan catatan request (opsional).
- Formulir rating produk (1–5 bintang) yang dapat diisi oleh pengguna yang sudah login. Setiap akun hanya dapat memberikan satu rating per produk dan dapat memperbaruinya.
- Keterangan bahwa pemesanan hanya simulasi.

**D. Autentikasi Pengguna**

Sistem autentikasi mencakup:
- Registrasi akun baru (`/daftar`) dengan validasi nama, email, dan password minimal 8 karakter dengan konfirmasi.
- Login (`/masuk`) dengan email dan password, dilengkapi proteksi rate limiting (maksimal 5 percobaan per menit per kombinasi email dan IP).
- Logout dengan invalidasi sesi dan regenerasi token CSRF.
- Redirect otomatis ke halaman yang dituju sebelum login (intended URL).
- Pesan dalam Bahasa Indonesia untuk seluruh validasi dan kesalahan.

**E. Keranjang Belanja**

Halaman keranjang (`/keranjang`) memungkinkan pengguna yang sudah login untuk:
- Melihat seluruh item dalam keranjang beserta detail produk.
- Mengubah jumlah item (1–99 per baris).
- Menghapus item dari keranjang.
- Validasi stok dilakukan secara transaksional dengan row locking untuk mencegah race condition.

**F. Checkout Simulasi**

Halaman checkout (`/checkout`) menyediakan proses pemesanan simulasi:
- Ringkasan pesanan yang menampilkan seluruh item, jumlah, harga satuan, dan total.
- Formulir data penerima meliputi nama dan alamat.
- Metode pengiriman dan pembayaran hanya tersedia opsi "simulasi" (pengiriman simulasi Rp0, pembayaran simulasi tanpa uang sungguhan).
- Checkbox persetujuan bahwa pesanan bersifat simulasi (wajib dicentang).
- Proteksi terhadap perubahan keranjang atau harga setelah halaman checkout dimuat, menggunakan mekanisme checkout token (UUID) dan validasi konsistensi data.
- Nomor pesanan otomatis dengan format `J2M-[ULID]`.
- Stok produk dikurangi setelah pesanan berhasil dibuat.

**G. Riwayat Pesanan**

Pengguna dapat melihat:
- Daftar pesanan (`/pesanan`) yang diurutkan dari yang terbaru, dengan paginasi 10 per halaman.
- Detail pesanan (`/pesanan/{order}`) yang menampilkan nomor pesanan, status, daftar item, dan total.
- Status pesanan mengikuti alur: Dibuat → Diproses → Selesai.

**H. Panel Administrasi**

Panel admin (`/admin`) dilindungi oleh middleware `AdminOnly` yang memeriksa apakah pengguna memiliki role `admin`. Fitur admin meliputi:

- **Dashboard** (`/admin`): Menampilkan jumlah produk aktif, jumlah pesanan, dan distribusi status pesanan.
- **Manajemen Produk** (`/admin/produk`): Daftar produk dengan paginasi, formulir tambah dan edit produk (nama, kategori, deskripsi, harga, stok, status aktif, penanda custom). Penghapusan produk dilakukan melalui soft-delete yaitu menonaktifkan produk dari katalog tanpa menghapus data historis.
- **Manajemen Kategori** (`/admin/kategori`): Daftar kategori beserta jumlah produk pada masing-masing kategori. Admin dapat menambah, mengubah nama, dan menghapus kategori (dengan syarat tidak ada produk yang masih terdaftar di kategori tersebut).
- **Manajemen Pesanan** (`/admin/pesanan`): Daftar seluruh pesanan dari semua pengguna, detail pesanan, dan kemampuan mengubah status pesanan secara bertahap (Dibuat → Diproses → Selesai).

**I. Fitur Teknis Pendukung**

- **Navigasi responsif:** Header menampilkan navigasi utama (Produk, Keranjang, Pesanan saya, Admin, Keluar) yang disesuaikan berdasarkan status login dan role pengguna.
- **Tautan eksternal di footer:** Footer memuat tautan Instagram J2M dan Shopee. Kedua tautan dibuka pada tab baru dengan perlindungan `noopener noreferrer`.
- **Skip link:** Tersedia link "Lewati ke konten" untuk aksesibilitas.
- **Tag `noindex, nofollow`:** Halaman website menggunakan meta tag robots `noindex, nofollow` karena sifatnya sebagai proyek simulasi.
- **Health check:** Endpoint `/health` mengembalikan response JSON `{"status":"ok"}` tanpa bergantung pada sesi atau autentikasi, digunakan untuk pemeriksaan liveness.
- **Proteksi keamanan:** File `.env`, `.git`, dan file tersembunyi lainnya diblokir oleh konfigurasi Caddyfile. CSRF protection aktif pada seluruh form. Rate limiting diterapkan pada endpoint login dan registrasi.

#### 3.1.4 Implementasi Katalog Produk

Katalog produk merupakan fitur inti website J2M. Implementasinya melibatkan beberapa komponen:

**Struktur Data Produk**

Data produk disimpan dalam tabel `products` dengan kolom: `id`, `category_id` (foreign key ke tabel `categories`), `name`, `description`, `price` (unsigned big integer dalam Rupiah), `stock`, `is_active` (boolean untuk mengontrol visibilitas di katalog), `requires_custom` (boolean penanda produk custom), dan timestamp.

Tabel `categories` menyimpan kategori produk (Bahan jok, Jok custom) yang berelasi one-to-many dengan tabel `products`.

Tabel `product_ratings` menyimpan penilaian pengguna dengan constraint unique pada kombinasi `product_id` dan `user_id`, memastikan satu rating per pengguna per produk.

**Seeder Produk**

Data produk awal diisi melalui `DatabaseSeeder` yang membuat dua kategori dan enam produk sesuai daftar harga J2M. Seeder menggunakan `firstOrCreate` untuk mencegah duplikasi saat dijalankan berulang.

Akun admin demo dibuat berdasarkan konfigurasi environment variable `DEMO_ADMIN_EMAIL` dan `DEMO_ADMIN_PASSWORD` (minimal 12 karakter). Tidak ada akun atau kredensial bawaan yang tertanam di source code.

**Foto Produk**

Enam foto produk tersimpan di direktori `public/images/products/`:
- `busa.jpeg` — Foto produk busa
- `fiber.jpeg` — Foto produk fiber / tulangan jok
- `kulit polos.jpeg` — Foto produk kulit jok biasa
- `kulit motif.jpeg` — Foto produk kulit jok motif
- `kulit motif(1).jpeg` — Foto ilustrasi untuk produk satu set jok custom
- `latex.jpeg` — Foto produk latex

Pemetaan foto ke produk dilakukan melalui method `imagePath()` pada model `Product`, yang mencocokkan nama produk (case-insensitive) dengan nama file foto. Foto untuk produk jok custom secara eksplisit ditandai sebagai ilustrasi melalui method `usesIllustration()` dan label "FOTO HANYA ILUSTRASI" pada tampilan.

#### 3.1.5 Deployment Website

Website J2M dikonfigurasi untuk di-deploy ke Vercel menggunakan pendekatan Docker container service. Konfigurasi deployment terdiri atas:

**Dockerfile (Multi-stage Build)**

Build dilakukan dalam empat tahap:
1. **Stage `base`:** Menggunakan image `dunglas/frankenphp:1-php8.3-bookworm` dan memasang ekstensi PHP yang diperlukan (ctype, dom, fileinfo, mbstring, pdo_mysql, opcache, zip).
2. **Stage `dependencies`:** Menyalin Composer dari image resmi, menginstal dependency production tanpa dev packages.
3. **Stage `frontend`:** Menggunakan Node.js 22 untuk menjalankan `npm ci` dan `npm run build` yang menghasilkan aset CSS/JS melalui Vite dan Tailwind CSS.
4. **Stage `runtime`:** Menyalin hasil build ke image final, mengatur permission untuk user `www-data`, dan mengekspos port 80 dengan perintah FrankenPHP.

**Caddyfile**

Caddy dikonfigurasi sebagai web server dengan fitur:
- Admin API dimatikan untuk keamanan.
- Auto HTTPS dinonaktifkan karena TLS diterminasi oleh Vercel.
- Root direktori mengarah ke `/app/public`.
- Kompresi zstd dan gzip diaktifkan.
- File tersembunyi (`.env`, `.git`, dsb.) diblokir dengan response 404.
- PHP request ditangani oleh `php_server` dengan fallback ke `index.php`.

**vercel.json**

Konfigurasi Vercel mendefinisikan satu service bernama `app` dengan entrypoint `Dockerfile` dan runtime `container`. Seluruh request di-rewrite ke service tersebut.

**Status Deployment**

Website J2M telah dipublikasikan pada https://j2m-jok-motor.vercel.app. Deployment menggunakan konfigurasi Docker, FrankenPHP, Caddy, dan basis data MySQL Railway. Pengujian otomatis lokal setelah penambahan rating dan tautan footer menghasilkan 29 test dan 535 assertions yang seluruhnya lulus. Konfigurasi environment production tetap dikelola terpisah dari source code.

### 4.3 Kendala Pelaksanaan

Selama pelaksanaan proyek, beberapa kendala yang dihadapi meliputi:

1. **Keterbatasan infrastruktur deployment:** Docker CLI/daemon dan Vercel CLI tidak tersedia pada lingkungan pengerjaan utama, sehingga build Docker dan deployment ke Vercel tidak dapat diverifikasi secara langsung selama proses pengembangan. Verifikasi dilakukan melalui test suite dan pemeriksaan manual terhadap konfigurasi.

2. **Kebutuhan database eksternal:** Deployment ke Vercel memerlukan database MySQL eksternal karena database lokal (Laragon) tidak dapat diakses dari lingkungan Vercel. Penyediaan dan konfigurasi database eksternal menjadi prasyarat tambahan yang harus dipenuhi.

3. **Keterbatasan data produk:** Deskripsi lengkap dan spesifikasi teknis untuk sebagian produk (busa, fiber, latex) belum tersedia dari pemilik usaha. Seeder mencatat "Deskripsi lengkap dan satuan produk belum tersedia" untuk produk-produk tersebut.
